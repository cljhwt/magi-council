# MAGI Council 产品需求文档

版本：v0.1｜日期：2026-11-04｜状态：立项草案，可进入原型开发

实施更新：用户已确定本轮不做语音。实现与验收状态以 README、VALIDATION.md 为准；下文语音部分保留为未来候选，不纳入当前版本。

## 1. 产品定义

一个受《新世纪福音战士》MAGI 启发的开源 AI 决策终端：用户提交一个问题，三个拥有独立提示词、独立上下文的 AI 从不同价值视角提出意见，经过有限讨论后投票，并在复古科幻终端上展示共识、异议和下一步建议。

一句话卖点：**把一个纠结的问题，交给三个立场不同的 AI 开会。**

暂定名称 MAGI Council；最终仓库名需检查重名。定位为非官方同人启发项目。第一阶段交付本地运行的独立 Web 应用，第二阶段开放模型配置，第三阶段适配 DeepSeek Harness，最后完成开源发布和传播物料。

## 2. 原作设定与产品改编边界

用户所说的机构为 NERV，系统为 MAGI。“三权分立”适合作为通俗描述，原作更准确的概念是三个不同人格侧面的合议系统，并非立法、行政、司法三个分支。

| 单元 | 原作人格侧面 | 产品中的职责（本项目改编） |
| --- | --- | --- |
| MELCHIOR-1 | 赤木直子作为科学家的一面 | 可行性、证据、逻辑、资源约束 |
| BALTHASAR-2 | 赤木直子作为母亲的一面 | 照顾受影响者、长期影响、风险与可逆性 |
| CASPER-3 | 赤木直子作为女人的一面 | 个人意愿、自主性、情感和价值选择 |

设定依据：TV 第 13 集及 [EvaGeeks MAGI 条目](https://wiki.evageeks.org/Magi)、[MAGI 设定整理](https://evangelion.fandom.com/wiki/Magi)。本次依据公开资料核对，开发前应回看合法片源中的第 13 集确认画面、字幕及名称。本项目不将人格改编表述为原作逐字设定，也不将上述视角解释为现实女性或母亲必然具有的特征。

多数决、全票模式、弃权及超时规则均为产品规则，不宣称完整还原原作所有场景。

## 3. 用户与核心体验

目标用户：EVA 爱好者、喜欢新奇 AI 工具的普通用户、希望研究多智能体协作的开发者。

核心场景：讨论一个个人选择、评审一个项目想法、比较多个方案。首发预置三个问题，例如“周末做开源项目还是休息”“一个人做独立游戏要不要先做 Demo”“要不要给这个项目增加语音功能”。

用户流程：打开终端 → 选择示例或输入问题 → 确认待表决提案 → 启动三个单元 → 观察意见与分歧 → 查看投票和少数意见 → 导出结果或修改条件重议。

体验要求：第一屏就看见三个单元；首个状态反馈在本地点击后 1 秒内出现；无 Key 用户可以体验明确标注的录制回放；真实会话与回放在界面和导出中始终可区分。

## 4. 范围与优先级

| 阶段 | 必须交付 | 本阶段不做 |
| --- | --- | --- |
| P0：可玩闭环 | 三单元界面、内置人格、独立首轮、有限互评、投票、异常状态、Markdown 导出、回放 Demo、服务端环境变量接入一个真实模型 | 登录、付费、长期记忆、自动执行外部操作 |
| P1：自由模型 | Provider 适配、三个单元分别选模型、连接测试、能力检测、限额与配置导入导出 | 承诺兼容所有 API |
| P2：宿主插件 | DeepSeek Harness 适配、会话输入输出、安装卸载验证、版本兼容说明 | 重写核心或同时支持大量宿主 |
| P3：开源传播 | 双语 README、许可与素材清单、发布包、截图、短视频、宣传文案、可选语音 | 首发强制部署高算力 TTS 服务 |

P0 只把 API 配置放在服务端环境变量里；Provider 抽象从第一天保留，用户配置页面在验收之后加入。

## 5. 三元协作协议

### 5.1 提案与状态

系统表决对象必须是一个明确的二元提案，例如“未来两周先开发无语音的 MAGI MVP”。用户可以直接输入提案；宽泛问题先由一次模型调用整理出候选提案，让用户编辑并确认。确认后本次投票期间不得修改命题。

状态：等待输入 → 提案确认 → 首轮独立评估 → 互评 → 终轮投票 → 裁决；异常出口包括已取消、预算耗尽、单元故障、需要补充信息。任一步均可取消；修改提案创建新一次运行。

### 5.2 上下文隔离与讨论

1. 三个单元获得相同的用户问题、提案和用户提供的资料，但分别使用独立系统提示词和消息历史。首轮不得读取其他单元输出。
2. 首轮全部结束后，同时向三个单元提供三份结构化意见，允许各自质疑关键假设或修订意见。
3. 默认首轮一次、互评一次，不开放无限循环。每个单元在互评回复中直接给出最终票。
4. 默认同一模型运行三个实例；P1 可选择三个不同模型。界面说明“上下文独立不代表统计独立，意见一致不等于事实正确”。
5. 调度、校验、计票由程序负责，不额外创建拥有裁决权的第四个 AI。只有有效意见可被展示和计票。

### 5.3 输出契约

每个单元输出：单元 ID、阶段、提案 ID、立场摘要、关键依据、假设、风险、对其他意见的回应、改变意见的条件、投票。投票枚举为 APPROVE、REJECT、ABSTAIN；首轮可无交叉回应。

展示可读的理由摘要及可核验来源，不要求暴露模型私有思维链；未接入检索时明确标注“未联网验证”。模型自报信心不作为概率或票数权重。

### 5.4 裁决规则

| 最终有效状态 | 默认多数决结果 |
| --- | --- |
| 三个单元均完成，至少两票赞成 | 通过；保留异议与条件 |
| 三个单元均完成，至少两票反对 | 否决；展示主要障碍 |
| 三个单元均完成，其余组合 | 暂缓；列出缺失信息 |
| 任一单元超时或故障 | 不完整，不输出正式通过或否决 |

可选“全票通过”模式：仅三个 APPROVE 算通过；任意有效 REJECT 算否决；其余完整运行算暂缓；单元故障仍算不完整。模式必须在启动前选定，并写入结果。不得把超时当反对票或弃权票。

输出固定包括：原提案、采用规则、三张票、共识、异议、待验证事实、下一步行动。聚合摘要如使用模型生成，必须独立标记且不得改写程序计算的结果。

## 6. 内置人格提示词要求

共同规则：讨论已确认提案；区分事实和假设；信息不足允许弃权；不给其他单元下指令；不能因角色扮演捏造来源；输出指定结构；在修订时说明变更依据。

| 单元 | 提示词核心 | 防止同质化的约束 |
| --- | --- | --- |
| MELCHIOR | 用证据与资源约束检验提案，指出最关键的可证伪假设，提出最低成本验证步骤 | 不把个人偏好当客观事实 |
| BALTHASAR | 检查相关人的利益、长期后果、失败代价与恢复路径 | 不为了谨慎而一律反对 |
| CASPER | 检查提案是否符合用户明确表达的愿望、自主性与价值取向 | 不擅自推断用户隐私或替用户定义幸福 |

提示词文件应版本化；运行记录保存版本号。P1 允许高级用户编辑并恢复默认值，编辑后的角色需标注“自定义”。

## 7. 界面与视觉素材

主界面采用深色背景、橙红状态文字、几何面板、三角分布的三个单元、中央裁决区。桌面端展示三面板；手机端提供纵向卡片和固定裁决摘要。状态同时使用文字和图标，避免只靠颜色辨别。

状态包括待机、评估中、赞成、反对、弃权、故障；点击单元展开理由。动效可关闭，音频默认静音，允许跳过动效直接查看结果。不制作虚假的实时思考文本或虚假百分比进度。

### 高清素材策略

目前找到公开 MAGI 设定和画面参考入口，但**未核实到同时具备高清源文件与明确再分发授权的官方原图**。百科图片可以帮助理解构图，不能据此当成可开源素材。原作画面参考：[EvaGeeks](https://wiki.evageeks.org/Magi)、[Fandom](https://evangelion.fandom.com/wiki/Magi)。

产品默认使用自行绘制的 SVG/CSS 界面，保证文字清晰并支持任意缩放；需要位图时导出 3840×2160 PNG。可生成原创科幻控制室背景，但生成内容应标注为原创视觉，不能称作“高清原图”。本 PRD 阶段不需要生成图片。

素材任务验收：每个候选资源记录来源 URL、作者、尺寸、授权说明、是否允许修改和再分发；授权不明的原作截图不进入发布包。若未来提供用户自带背景，只从用户本地加载。仓库代码许可与图片、字体、声音许可分别记录。

## 8. 技术方向与框架取舍

建议采用 TypeScript 核心与 Web 前端；框架版本在技术验证时锁定，不在 PRD 中写死最新版本。通过事件流驱动界面，将决策核心、模型适配、界面和宿主适配拆开。

| 参考框架 | 已核实能力与借鉴点 | 本项目取舍 |
| --- | --- | --- |
| [LangGraph](https://github.com/langchain-ai/langgraph) / [多智能体文档](https://docs.langchain.com/oss/python/langchain/multi-agent) | 状态工作流、上下文管理、子智能体协作；提供 JS/TS 实现入口 | 优先验证 LangGraph.js 的有限状态图与并行汇合；若依赖明显超过收益，使用等价的小型状态机 |
| [CrewAI](https://github.com/crewAIInc/crewAI) | 角色协作与事件驱动 Flows | 借鉴角色配置，不作为首发 Python 运行时依赖 |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | 插件化宿主，可扩展 agent 能力和界面 | P2 做薄适配层，复用决策核心 |

推荐逻辑分层：Web UI → 会话服务/事件流 → MAGI 决策核心 → 模型 Provider；DeepSeek Harness Adapter 同样调用 MAGI 决策核心。

P0 核心事件至少包括 run.started、agent.started、agent.completed、agent.failed、vote.finalized、run.completed、run.cancelled；携带运行 ID、单元 ID、轮次及时间戳，支持重连后获取当前快照。回放按记录事件播放，不重新请求模型。

## 9. 模型 API 配置与运行约束

P1 最先支持经实际测试的 OpenAI-compatible Chat Completions 接口和 DeepSeek 接口；兼容协议不代表保证所有服务商、所有模型均可用。其他原生协议按后续需求增加适配。

每个单元可配置 Provider、Base URL、模型 ID、密钥引用、输出长度、超时；温度等参数只在服务商支持时展示。连接测试覆盖鉴权、模型可用、流式与结构化输出能力；不支持原生 JSON Schema 时采用文本 JSON 校验路径。

密钥由服务端读取或存储，前端只显示掩码；不得写入浏览器本地存储、结果导出或日志。配置导出默认不含密钥。本地版允许用户指定自己的网关；公网部署应对目标地址做限制并设置访问控制，不能成为开放代理。

默认调用预算：明确提案下为 3 次首轮 + 3 次互评；宽泛问题整理提案最多增加 1 次，模型摘要最多增加 1 次。每个失败单元每阶段最多重试 1 次；重试同样计入预算。默认硬上限 14 次调用、单调用 60 秒、一次运行 180 秒，均可由部署者下调。

启动时展示预计调用数与输出上限。Token 用量优先采用服务商返回数据；费用仅在已配置价格时估算，并标注估算。预算耗尽停止新调用；取消后丢弃迟到输出，尽力终止请求，已经产生的费用仍记录。

## 10. DeepSeek Harness 插件要求

官方已提供插件化运行时和[插件市场说明](https://deepseek-harness.github.io/deepseek-harness/en/guide/plugin-market)。官方也说明当前为 public preview，核心和 API 仍在演进，因此插件进入开发前先锁定目标宿主版本并检查当时的 SDK 与示例。

技术验证必须确认：工具注册、会话调用、模型调用入口、事件回传、界面扩展、取消及插件卸载清理。不得预先假设宿主一定提供三个独立的模型配置或完整自定义面板。

最小插件：提供 magi_deliberate 工具，将问题提交给核心并返回三方意见和程序裁决。增强版再提供 MAGI 面板。优先使用宿主凭证机制；宿主不能按单元选择模型时，明确降级为共用一个模型。保持独立 Web 版可用。

插件验收：在记录版本的干净宿主中完成安装、一次真实讨论、取消、重启、卸载；不修改宿主源码。发布信息声明支持版本，使用官方兼容字段，不自行杜撰安装命令或生命周期接口。

## 11. 可选语音与配音探索

配音目标是让三种视角有可辨识的原创声音：MELCHIOR 冷静清晰，BALTHASAR 温和稳重，CASPER 自信灵动。播报短摘要和投票结果，避免长篇逐字朗读拖慢节奏。

| 候选 | 适合验证的方向 | 选型门槛 |
| --- | --- | --- |
| [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) | 自由声音设计、风格指令、流式语音 | 中文自然度、三角色区分度、部署资源 |
| [CosyVoice](https://github.com/QwenAudio/CosyVoice) | 多语言语音、中文表现、流式部署 | 安装难度、首音延迟、目标硬件表现 |
| [Fish Speech](https://github.com/fishaudio/fish-speech) | 表现力和角色化朗读 | 选定模型权重及服务的实际许可、资源成本 |

这些为调研候选，尚未进行试听或性能实测，不宣称已经选出最好方案。代码、权重与在线服务条款需分别核对。

探索交付：三角色各三条短句，中文与中英混读至少各一条；固定脚本、记录模型/声音版本、硬件或服务、首音延迟、完整生成时长和费用。邀请至少 5 人盲听，至少 4 人能正确区分三种角色；最终按质量、资源和许可选一个方案。

默认使用原创设计音色或明确授权音色，原作台词音轨和声优录音不进入默认素材。TTS 故障只影响声音，不影响投票结果；支持停止、音量、字幕和逐单元播放。首发视频可先离线生成配音，无需把 TTS 部署列为核心应用前置条件。

## 12. 验收标准

以下均为开发目标，当前没有实测结果。

| 项目 | 通过标准 |
| --- | --- |
| 真实闭环 | 明确提案完成三单元首轮、互评、最终票、裁决与导出；同一次运行可追溯 |
| 独立性 | 检查请求记录，首轮各单元未收到其他单元输出；提示词、历史、模型配置可区分 |
| 计票正确 | 覆盖三种有效票的全部 27 个组合，以及单元故障；结果符合所选规则 |
| 异常处理 | 注入鉴权失败、429、超时、格式错误、取消、预算耗尽；无假票、无无限重试 |
| 配置安全 | 仓库、前端资源、日志与导出文件均不出现测试密钥；UI 仅展示掩码 |
| 协作质量 | 20 道固定场景题由 2 名评审打分；至少 16 题体现两个以上不同视角，摘要完整保留有实质内容的异议 |
| 基线比较 | 同一题集比较单模型单次回答，记录成本、延迟、遗漏与有用性；不以多智能体身份自动宣称更准确 |
| 使用体验 | 本地运行首个状态反馈 ≤1 秒；目标模型/网络环境下完整运行成功率 ≥90%，报告环境、样本量与延迟分布 |
| 响应式 | 390px、768px、1440px 宽度下可读可操作，无关键内容横向溢出；可关闭动效 |
| Demo 诚实性 | 回放全程标记，无 Key 不发模型请求；真实失败不会切换为假结果 |
| 发布就绪 | 干净环境按 README 启动成功；素材来源完整，截图与视频对应实际能力 |

20 道题建议由 8 道价值冲突、4 道信息不足、4 道资源约束、4 道明显可行或不可行问题组成。用真实结果评估分歧质量，不能强迫三个单元为了效果而唱反调。

## 13. 里程碑与交付物

以一名熟悉 Web/LLM 的开发者为假设，预计 3–4 周，不含外部授权等待；属于初步估算。

| 里程碑 | 预计投入 | 交付与进入下一阶段的条件 |
| --- | --- | --- |
| M0 设定与视觉验证 | 1–2 天 | 设定说明、素材登记表、原创界面草图、明确一条演示故事 |
| M1 协作核心 | 3–4 天 | 三角色提示词、状态机、结构化协议、一个真实 Provider、计票与异常验证 |
| M2 可玩 MVP | 3–4 天 | 终端 UI、真实讨论、回放、导出、20 题初测；P0 验收通过 |
| M3 自由配置 | 2–3 天 | 单元独立配置、连接测试、用量与限额、配置安全检查 |
| M4 Harness 适配 | 2–4 天 | 先完成兼容性验证，再交付最小插件；受宿主 API 实际情况影响 |
| M5 发布与传播 | 2–3 天 | 双语 README、版本发布包、演示视频、文案、配音样片与选型记录 |

开发顺序以 M0–M3 为主线；M4 可在独立版发布之后补充，不让宿主兼容问题阻断可用版本。

## 14. GitHub 发布与传播

宣传口径草案：

> 我把 EVA 里的 MAGI 做成了一个开源 AI 终端。一个问题，交给三个不同立场的 AI：检查证据、权衡后果、尊重你的选择。先独立判断，再互相质疑，最后投票。你能看到共识，也能看到没被多数票消掉的异议。

60 秒视频脚本：

| 时段 | 画面与内容 |
| --- | --- |
| 0–5 秒 | 实机亮起三个单元；字幕“如果三个 AI 对你的决定意见不一？” |
| 5–15 秒 | 输入一个真实问题并确认提案，展示独立评估状态 |
| 15–32 秒 | 切换三个角色的短意见，突出一个真实分歧；长等待明确标记加速 |
| 32–45 秒 | 展示互评和最终票，突出少数意见仍被保留 |
| 45–53 秒 | 展示真实可用的模型配置或导出；未发布功能不拍成已完成 |
| 53–60 秒 | GitHub 地址、启动入口和“非官方 EVA 启发项目”说明 |

同步准备 16:9 横版和 9:16 竖版，使用实机录屏、原创音效和已核对许可的音乐。至少提供一份无配音字幕版。传播效果观察 README 访问到启动尝试的转化、首次完整讨论完成率、问题反馈；不以未经证实的 Star 目标作为产品验收门槛。

## 15. 主要风险与默认决策

| 风险 | 应对 |
| --- | --- |
| 三个角色说同样的话 | 首轮隔离、角色评估标准明确、有限互评、固定题集人工检查 |
| 多数一致但共同出错 | 展示假设、来源状态和异议，保留单模型基线，不宣传投票即真理 |
| 动画好看但无实际帮助 | 每次输出可操作的验证步骤与改变立场条件 |
| 调用成本和延迟放大 | 两轮上限、调用和时间预算、取消、回放演示 |
| 原作素材无法再分发 | 默认原创界面；原图仅作为出处明确的研究参考 |
| 插件 API 演进 | 核心独立、锁定宿主版本、先做兼容性验证 |
| 配音拖慢首发 | 作为可选增强，先为宣传视频离线生成 |

默认假设：中文优先、本地自部署、无账号、用户自备模型 Key、网页先行、代码拟采用 MIT、无外部自动执行能力。项目名、最终视觉稿、代码许可和配音供应商在各自里程碑根据实际结果定稿，不阻断原型开发。
