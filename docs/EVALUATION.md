# 人工评估题集

状态：题集已准备，尚未运行真实模型与人工评分。每题至少比较三元系统与同模型单次回答，记录：耗时、Token、费用（如可得）、遗漏、视角区分、异议保留、行动建议。不要用固定脚本回答这些问题。

## 价值冲突（8 题）

1. 本周末一天做开源项目、一天休息。
2. 为了更快发布，首版只支持中文。
3. 接受薪水更高但需要频繁加班的工作。
4. 把一个受欢迎的个人项目交给社区共同维护。
5. 为了照顾家人，放弃一次外地工作机会。
6. 先发布简洁但可用的界面，再打磨视觉效果。
7. 将空闲时间的一半用于学习新技术，而非熟悉的兴趣爱好。
8. 为追求个人创作自由，选择收入更不稳定的职业路径。

## 信息不足（4 题）

9. 在没有用户反馈的情况下全职开发这个产品。
10. 不知道预算和使用频率时购买一台高性能工作站。
11. 在未提供体量、硬件和并发需求时改用本地模型。
12. 在没有说明合作条款的情况下接受合伙邀请。

## 资源约束（4 题）

13. 两周、单人开发条件下先做无语音的 MAGI MVP。
14. 每月固定低预算下默认启用六次模型调用。
15. 只有普通笔记本时先使用远程 API 而非本地大模型。
16. 一个维护者同时支持独立 Web、桌面应用和五种插件宿主。

## 明显可行或不可行（4 题）

17. 在发布公开仓库前从提交内容移除 API Key。
18. 将三个模型都超时的结果显示为全票通过。
19. 给固定脚本演示明确添加回放标签。
20. 在没有任何授权说明时将原作声优录音作为默认开源素材发布。

每题由两人独立评审。有充分理由的一致意见属于有效结果，不要求为了展示效果而制造分歧。第 18 题同时应用于程序规则检查：模型意见不得改变故障不计票的硬约束。
