# v0.1 开发预览验证记录

日期：2026-11-04。环境：Windows、Node.js 24.11.1，Playwright Chromium。

## v0.2 Agent 背景接入（2026-11-06）

十四项自动化检查通过，包括所有六次评估收到同一背景、事实来源必填、辅助密钥脱敏、HTTP 背景传递和 Codex 插件客户端。技能校验器通过。Codex CLI 完成本机安装，Harness SDK 接受带 `context_json` 的工具定义。

使用已安装插件客户端和本机已配置的 `qwen3.8-max` 做过一次真实端到端验证：仅传入本会话相关的三条事实及来源，完成六次模型调用、三方终票与裁决。输出包含事实来源，并保留预算和跨聊天检索范围两个未知项。此为单个样例的通路验证，不代表长期决策质量已验证。未将测试请求或模型完整输出提交到仓库。

当前聊天安装后不会自动重载技能；桌面新会话中的自然语言触发、跨聊天检索和 Harness 完整生命周期仍需分别验证。

## v0.1.2 首次使用修复

复现：三个单元无 Key 时启动，原页面提前关闭输入窗口，仅在底部小字显示错误。

修复后，Playwright 回归函数 `tools/verify-onboarding.js` 验证通过：空提案不发请求；缺少 Key 不请求运行接口且保留提案；配置入口、一键复制、保存后返回；模拟 503 在提案窗口显示错误；部分单元缺少 Key 会指出单元；从提示进入回放不会调用运行接口。测试在浏览器拦截接口，未保存虚构 Key 到本机服务。

`npm test` 当前九项通过，增加了 DeepSeek 专用参数隔离和鉴权错误提示检查。默认模型依据 DeepSeek 官方文档更新为 `deepseek-flash`；真实付费模型质量与性能仍未验证。

主屏改为 4:3 经典多边形 MAGI 画面，输入和详情移入弹窗。重新运行七项测试全部通过。浏览器检查：1440×1080 桌面、390×844 手机、回放时单元颜色与裁决、单元点击打开详情、提案输入弹窗。未发现控制台错误。此项为画面与交互验证，不表示与某一原帧逐像素一致。

## 已验证

- `npm test`：7 项测试通过。
- 多数决与全票规则分别覆盖全部 27 种有效票组合。
- 首轮上下文隔离、首轮故障不进入正式计票、取消后不产生正常完成结果。
- 本地模拟 Chat Completions Provider 实际 HTTP 请求：保存三单元配置、响应不包含密钥、完整六次调用、互评包含三份首轮意见、429 时中断为不完整、拒绝跨来源请求。
- Harness 适配复用核心、响应宿主取消信号；本机 `@deepseek-ai/dsh-tools@0.1.5-rc.2` 的 defineTool 接受该工具定义。
- 浏览器：固定脚本回放完成、意见展开、配置弹窗；1440px 和 390px 视口检查，无明显布局溢出。
- 修复了最初的空样式导入和 favicon 控制台报错；刷新后控制台 0 errors / 0 warnings。
